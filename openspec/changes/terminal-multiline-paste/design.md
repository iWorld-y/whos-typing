# Design

## Context

现有 `Session.Execute` 根据 Shell 提示符和命令状态决定是否提交新命令。窗口的粘贴路径经 MyGo 编码后进入同一终端输入队列。隔离 MySQL 8.0.36 的客户端未启用括号粘贴。带分号的单行等待 Enter，含换行的输入可以立即执行首条 SQL。

## Goals / Non-Goals

**Goals**

- 用一个独立的粘贴操作覆盖 MySQL、REPL 和终端编辑器，并保留现有输入队列中的顺序和控制权保护。
- 让确认条件可验证，确认内容与实际发送的文本和窗格一致。

**Non-Goals**

- MySQL 结果解析、查询完成判断、Shell 命令执行改造、自动 Enter 和任意按键发送均不在此次范围内。

## Decisions

### 独立的 CLI 操作与终端写入回执

拟采用 `whos-typing-cli --session <id> session paste --stdin`，从标准输入读取一次 UTF-8 文本，不丢弃末尾换行。协议为该操作声明独立能力，绑定同一服务实例及稳定会话 ID。服务拒绝空文本和非文本控制字符，允许制表符及换行。不发送文本到系统剪贴板。

窗口控制器管理确认及窗格生命周期，Shell 会话负责写入仲裁。粘贴排队后与人工输入、接入和命令写入保持顺序。使用独立请求标识在实际写入时校验控制权、目标状态和确认，写完后再回执。普通人工输入守卫不得误吞已授权的粘贴，也不得被粘贴入口放宽。已知未提交人工输入、接管、并发写入和未知的既有 Agent 请求均阻止发送。与 Shell 有关的 `ready` 和 `pending` 可用于理解状态，不能直接用作粘贴必须等到 Bash 提示符的条件。

### 括号粘贴以终端解析器的当前模式为准

括号粘贴对应 DEC 私有模式 2004。终端处理 `CSI ? 2004 h` 开启及 `CSI ? 2004 l` 关闭，并按终端重置语义更新。读取目标 MyGo 终端的解析状态或验证本次编码结果，避免通过提示符、程序名称或原始输出中的字符串猜测。在确定使用括号粘贴时，由终端为整段文本生成边界，不能强制向未开启该模式的程序发送边界。

MyGo v0.7.4 的 `Terminal.Paste` 在内部读取模式并可能走应用主动读取文本的粘贴协议，公共接口未提供直接读取 2004 状态并与入队原子绑定的能力。实现时应验证受支持的模式读取和编码能力，保持上游依赖。如果无法在使用时可信核对模式与实际编码，则将模式判为未知，多行一律要求在目标窗格确认。只有确定这次发送会按括号粘贴编码且输入状态允许时，才走免确认路径。若程序走主动读取文本的协议，必须等文本实际被读取并写完才可返回已发送。

### 确认只对当前窗格和本次文本有效

| 发送条件 | 处理方式 |
| --- | --- |
| 已知密码提示、未提交人工输入、人类已接管或其他 Agent 请求正在写入 | 拒绝，不弹出可绕过保护的确认 |
| 含回车或换行，括号粘贴关闭、无法验证或实际发送方式不确定 | 在目标窗格确认，预览文本并提示换行可能立即提交 |
| 单行，或可验证将以括号粘贴发送的多行 | 输入状态可信且允许时可直接发送，状态不明时在目标窗格确认 |

确认界面标明会话 ID 和标签页，并允许在目标窗格完整审阅原文本，显示末尾换行。确认时由用户核对当前程序是否可接收该文本，尤其是远端进程组不可见时。确认期间的终端输入、输出、可观察的前台状态变化、取消或关闭均使本次申请失效。发送前复查这些条件并绑定原目标，确认和写入之间不会因切换焦点而改投另一个窗格。常规远端接入的自动允许设置不适用于此确认。

## Risks / Trade-offs

- 括号粘贴只传达文本边界。前台程序仍可能执行内容，尤其是未启用括号粘贴时的换行，因此预览和无额外 Enter 的约束都要保留。
- SSH 无法可靠识别远端正在读取输入的进程或所有密码提示。遇到不明状态时由用户核对实际窗格，已知的密码提示直接拒绝。
- 回执丢失或部分写入后，重试可能重复执行。CLI 保留发送状态未知，并让调用方查看原窗格。

## Migration Plan

先部署声明粘贴能力的 GUI，再使用新版 CLI。旧 GUI 只提供既有操作时返回升级提示。回退时可继续使用原有的 Shell 执行、终端快照和窗口粘贴。
