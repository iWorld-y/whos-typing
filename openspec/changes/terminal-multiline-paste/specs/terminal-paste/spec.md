# Spec Delta

## Purpose

为 Who’s Typing CLI 提供通用的前台终端文本粘贴能力，使调用方可以向已打开的交互程序发送多行文本，并在终端状态不明确时由用户核对目标和内容。

## ADDED Requirements

### Requirement: 粘贴到指定窗格的前台程序

CLI SHALL 要求调用方提供完整会话 ID，并仅向该窗格发送文本。系统 SHALL 保留行序、空行、缩进和末尾换行，按终端粘贴协议编码，且不得添加 Enter 或拆成多次粘贴。此操作适用于本地和 SSH 窗格，无需 Bash 接入。空文本和含 ESC、NUL 等非文本控制字符的请求 SHALL 被拒绝。

#### Scenario: 向支持括号粘贴的编辑器发送多行文本
- **WHEN** A 的编辑器启用了括号粘贴且允许发送，CLI 指定 A 并提供含缩进和空行的文本
- **THEN** 系统仅在 A 中发送一次括号粘贴，保留文本内容和换行
- **AND** 系统不发送额外的 Enter

#### Scenario: 目标不可用或旧 GUI 不支持粘贴
- **WHEN** CLI 省略目标、提供未知或已关闭的 ID，或 GUI 未声明支持粘贴
- **THEN** CLI 返回明确错误，且不回退到当前窗格或普通命令执行

### Requirement: 按当前粘贴模式决定确认

系统 SHALL 根据目标终端当前解析的括号粘贴模式判断多行输入。只有能确定本次发送将使用括号粘贴时，才可因模式跳过确认。模式关闭、无法可信读取或实际发送方式不确定时，含回车或换行的文本 SHALL 在目标窗格确认。无法确定前台程序可以接收输入时，单行也 SHALL 确认。系统 SHALL 在队列写入前复查确认条件。

#### Scenario: MySQL 未启用括号粘贴
- **WHEN** A 停在 MySQL 提示符且未启用括号粘贴，CLI 发送含换行的文本
- **THEN** A 显示待发文本和「换行可能立即提交」的提示，确认前不发送任何内容
- **AND** 用户可确认发送一次，也可取消并保留原会话

#### Scenario: 模式未知或入队后改变
- **WHEN** A 无法读出可信模式，或免确认的多行请求在写入前已不再满足括号粘贴条件
- **THEN** 只有用户查看 A 并确认当前请求后才可发送
- **AND** 自确认展示起条件再次发生变化时，旧确认失效

### Requirement: 确认绑定目标窗格与原始文本

确认 SHALL 展示目标窗格、会话 ID 和完整可审阅的文本，标明换行和尾随换行。用户 SHALL 确认可向当前前台程序粘贴。确认仅对该次请求有效。取消、超时、断开、目标关闭，或确认期间出现新的输入、输出或可观察到的前台状态变化 SHALL 使请求失效。系统 SHALL 拒绝向已知密码提示、已知未提交人工输入或人类主动接管的窗格发送。

#### Scenario: 切换窗格后确认
- **WHEN** 用户查看 A 的确认请求后切换到 B
- **THEN** B 不显示可用于批准 A 的确认按钮，返回 A 后才能确认
- **AND** 任何内容都不会被发往 B

#### Scenario: 确认期间有新输入或输出
- **WHEN** 用户查看确认后，目标窗格出现新的输入、输出或可观察到的前台状态变化
- **THEN** 系统作废确认，旧请求不写入，CLI 提示重新核对窗格

#### Scenario: 人类接管或发生输入冲突
- **WHEN** 用户已主动接管，目标已有未提交人工输入，或另一项 Agent 请求正在写入
- **THEN** 系统拒绝粘贴，且不清空原输入、不终止前台程序、不延后自动发送

### Requirement: 报告粘贴发送状态

CLI SHALL 区分已发送、未发送和发送状态未知。成功 SHALL 只表示粘贴文本已完整写入终端连接。无法确认完整写入时 SHALL 报告状态未知且不自动重试。调用方可继续用终端快照查看画面。

#### Scenario: 写入过程中断
- **WHEN** 粘贴已开始写入，但连接断开且无法确认完整写入
- **THEN** CLI 不将申请确认或入队当作成功，也不自动重发
