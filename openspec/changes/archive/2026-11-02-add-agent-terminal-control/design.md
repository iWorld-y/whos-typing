# Design

## Context

现有 `internal/shell` 将 CLI 请求放入输入队列，在接受请求后设置 `active`，再根据 Shell 的开始、结束及提示符标记完成请求。`SetStateHandler(bool)` 只反映单次执行或远端自动接入输入，窗口用它更新标题；远端请求超时后 `active` 可以清空，命令却仍可能运行。

`internal/control` 每次 CLI 调用使用独立 socket 连接，`session read` 单独读取终端快照。窗口目前直接显示 `terminal.View` 和远端接入确认框。项目使用上游 MyGo v0.7.3；参考示例使用 v0.7.4 的 `ui/shader`、`DrawOver` 和动画接口。需求见 `proposal.md`，可观察行为见 `specs/`。

## Goals / Non-Goals

**Goals:**

- 控制权跨多次 CLI 调用保持，并与实际命令执行状态分开记录。
- 立即响应手动接管，保持正在执行的命令和只读观察能力。
- 让自动交还、手动接管、远端状态不明和 CLI 输入竞争都有明确结果。
- 在真实 MyGo 终端中复用参考特效，同时保持内容、焦点和控制按钮可用。

**Non-Goals:**

- 不增加任务终止按钮，不管理后台服务或 Agent 的其他工作。
- 不引入 Agent 身份认证、多窗口协作、网络控制服务或本地 MyGo fork。
- 不改变远端 Bash 接入的目标确认、超时未知结果和禁止盲目重试的约束。

## Decisions

### 独立维护控制权和命令状态

在 Shell 会话的同步边界内维护三种控制状态：人类可自动让出、Agent 控制、人类手动接管。启动时进入人类可自动让出状态；Agent 持有控制权时主动交还或空闲超时交还，也进入该状态。用户点击「接管」进入人类手动接管状态；只有用户点击「交还 Agent」且终端可安全接收命令，才退出手动接管状态。人类手动接管期间收到 CLI 主动交还请求，也不能解除该状态。

在前一种人类状态下，CLI 的执行请求或经确认的自动接入输入可在现有空提示符、未提交输入和远端就绪检查通过后获取 Agent 控制权。手动接管状态拒绝这些请求，并返回清楚的状态信息；`session read` 始终只读，不获取控制权。手动远端接入只输出接入说明并等待人工输入，保留现有流程；自动接入仍先由窗口确认，再执行输入安全检查。

命令队列、发送中、正在运行、已确认结束及结果未知继续独立于控制权。不能直接用现有 `active` 或标题的布尔回调表示控制权：命令间 Agent 仍拥有控制权，而人类接管后命令也可能继续运行。

### 在输入入口串行化切换与发送

沿用现有输入队列和 Shell 状态锁，把控制权判断、命令受理和队列屏障校验放在同一同步边界。用户接管使尚未开始发送的排队请求失效，CLI 得到未执行结果；交还后不重放被拒绝或取消的请求。

对已经开始的命令保留输出和结果跟踪，切换为人类控制后立即放行人工键盘与粘贴，使输入进入当前前台程序。接管不发送 Ctrl+C，也不等待前台程序退出。对于已经开始但结果无法确认的写入，报告状态未知，不假定未执行或自动重试。Agent 读取快照及原请求接收输出不依赖写入控制权。

保留已有 Ctrl+C 行为和远端自动接入确认。被人类接管时，新的 CLI 自动接入请求不得向终端发送内容；确认等待期间发生终端变化仍按现有规则取消。

### 扩展现有 CLI 控制协议

所有通过 CLI 发送到终端的执行或自动输入都按 Agent 操作处理，不要求额外的身份参数。保留现有命令调用、`--timeout`、`session read` 和远端接入命令格式。增加 `session release` 作为 Agent 主动交还入口，并提供只读的控制状态查询，使调用方能区分人类接管与终端暂忙。

已被拒绝的执行请求立即返回，不在后台排队等待交还。调用方获知控制权恢复后，先按需读取终端状态，再决定下一条命令；不自动重试原请求。状态查询和屏幕读取不刷新空闲时间，也不修改控制权。socket 的当前用户隔离、窗口锁和关闭行为保持不变。

### 从已确认的命令结束时计算空闲时间

Agent 获得控制权后，已受理但尚未发送、正在发送或正在运行的请求都阻止自动交还。命令确认结束时记录单调时钟并开始 60 秒计时；新执行请求被受理时取消旧计时，等待新命令结束后重新开始。人类点击「交还 Agent」且没有运行命令时，从交还时刻开始计时。

计时器触发时，在控制权同步边界内重新检查当前控制方、计时版本、待发送请求和命令状态，避免到期与新请求或人类接管并发时误交还。人类手动接管期间不运行自动交还计时，继续保留「交还 Agent」入口。

计时依据前台 CLI 命令本身，而非它启动的服务或后台进程。远端超时、断线或发送不完整导致命令状态未知时不能当作已结束；只有后续标记能确认状态时才恢复计时，用户始终可以手动接管。

### 在终端内容上绘制特效

以参考示例中的蓝色边缘光带、点阵、渐变和鼠标附近亮度变化为视觉依据，将所需 shader 资源纳入项目。保持 MyGo 指向上游 v0.7.3，先验证示例着色器在该版本可编译及可绘制；不依赖参考目录作为运行时路径。

在终端内容的父元素上使用 `DrawOver`，由独立底部控制栏显示状态和按钮；远端确认框保持在特效之上。状态变化通过窗口更新机制投递到界面线程。特效不接管键盘或鼠标事件，鼠标亮度变化不得影响选择和滚动。

根据真实终端的深色背景调整透明度，避免遮挡文字和底部提示符。仅在效果可见时请求动画帧；启用系统减少动态效果时保留静态状态提示，不持续刷新。真实窗口中验证尺寸变化、终端重绘、关闭以及绘制性能。

## Risks / Trade-offs

- [远端超时后命令可能仍运行] → 将结果未知作为独立状态，不用 `active == nil` 判断空闲；用户可手动接管。
- [切换时旧 CLI 写入与人工输入竞争] → 队列和控制权一起校验；未发送请求失效，已发送但结果未知时报告未知，不重试。
- [人工操作可能改变工作目录或远端会话] → 拒绝并丢弃接管期间的新 Agent 写入；交还后要求调用方重新观察，不自动执行旧请求。
- [全窗口 shader 可能影响帧率和文字对比度] → 限制无意义的重绘并按需降低刷新频率，在 macOS 真实终端验证效果和性能。
- [参考示例使用较新的 MyGo] → 先在 v0.7.3 验证 shader 和鼠标事件，再决定兼容写法；不通过 fork 或 `replace` 解决。

## Migration Plan

保留现有 CLI 调用格式；新增状态查询和主动交还入口，并在项目使用文档中说明所有 CLI 执行均视为 Agent 操作。人类接管时，旧格式的 CLI 写入同样会被拒绝，提示用户交还控制权。

回退时同时移除控制权状态、入口和界面提示，并恢复原有 CLI 命令期间输入保护；不修改用户 Shell 配置或远端持久文件。
