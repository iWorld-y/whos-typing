# Design

## Context

动机见 proposal.md。当前仓库只有 OpenSpec 配置，没有 Go 模块、应用源码或测试。已读取本地 MyGo 的 README、终端插件文档和 `examples/terminal/main.go`；它们展示了 `terminal.New`、`terminal.View`、Shell 退出回调和窗口关闭清理。CodeGraph 查询因数据库无法打开而失败，源码检查采用限定文件读取。

用户确定使用 Go、MyGo 原生客户端，以及仅含本地 Shell 交互的 MVP。依赖来源必须是原始提供方 `https://github.com/egoist/mygo`。本地参考资料不是上游版本能力的保证，实施时必须核对所固定版本包含原生终端插件。

## Goals / Non-Goals

**Goals:**
- 使用 MyGo 原生视图呈现一个持续存在的本地 Shell，会话行为遵循 `specs/local-terminal/spec.md`。
- 将入口编排与窗口、终端生命周期分开，保持最小工程结构。
- 以当前 macOS 环境作为首个验收平台，记录工具链和原生库前提。

**Non-Goals:**
- 不在本次引入前端 WebView、终端协议自研实现、后台服务或跨进程通信。
- 不预留 Agent 服务接口或通用会话抽象；本版功能边界见 proposal.md。
- 不承诺 Windows、Linux 的运行验收或发行包交付。

## Decisions

### 1. 固定原始上游依赖

使用 Go 模块 `github.com/egoist/mygo`，在实现时选择包含 `ui` 和 `plugins/terminal` 的上游版本并写入 go.mod/go.sum；没有对应标签时固定上游提交的伪版本。不得使用 fork、本地 `replace` 或依赖开发者的 go.work 才能构建。

本地参考版本要求 Go 1.27.3，最终工具链约束以所固定上游版本的 go.mod 为准。终端依赖 libghostty-vt，按照该版本的 MyGo 加载与校验机制处理，不复制或改造库加载器。若上游缺少已观察到的 API，应明确报告阻塞，不以本地替换绕过用户约束。

替代方案是直接链接本地框架，虽便于调试，但会破坏依赖来源约束和可复现性，因此不采用。

### 2. 单进程与最小目录结构

采用 `cmd/whos-typing/main.go` 作为启动入口，`internal/app` 承担窗口创建、终端视图和生命周期处理。入口只调用应用运行函数并输出错误，不包含终端业务逻辑。开发与验收说明写入 `docs/development.md`。

应用进程直接持有一个终端实例。相比独立会话服务，此结构足以覆盖单窗口本地终端，避免提前引入 IPC 和服务管理。

### 3. 复用原生终端插件

窗口标题设为 `Who's Typing`，内容使用 `ui.View` 与填满窗口、自动聚焦的 `terminal.View`。初始尺寸沿用上游示例量级，允许用户调整窗口大小；本版不增加标签页、侧栏或配置界面。

使用插件默认的本地用户登录 Shell 与初始目录，不逐条启动新 Shell。键盘、退格、回车、Ctrl+C 和终端输出均交给插件及 Shell 处理，不自行解析命令。相比普通文本输入框，此方式保留真实终端交互和连续会话状态。

### 4. 明确退出与失败路径

窗口关闭时释放终端实例并退出应用；Shell 退出回调请求关闭窗口。关闭路径需要防止重复释放，并通过 MyGo 支持的线程调度接口执行 UI 操作。

上游示例用窗口就绪信号处理 Shell 提前退出的情况，应用沿用同等时序保护，避免访问未创建的窗口。关闭最后一个窗口是否自动退出必须在选定版本中验证，必要时显式调用应用退出接口。

原生库或 Shell 启动失败时向调用方返回错误，由入口写入标准错误并非零退出。终端创建后的失败路径必须释放已创建资源。对于延迟启动暴露的错误，使用选定上游版本实际提供的错误反馈，不将仅返回退出码的回调描述成完整错误原因。

### 5. 验证以可见行为和生命周期为主

实现后运行格式、构建、vet 和相关测试。对应用新增的生命周期逻辑编写定向测试，覆盖启动失败、提前退出和重复关闭；不重复测试 MyGo 的终端转义序列实现。

在真实 macOS 桌面中验证窗口与输入焦点、`echo`、分次输出、`cd`、环境变量、Ctrl+C、`exit` 和关闭窗口。检查窗口关闭后应用与其直接创建的 Shell 均结束。仅有编译通过不能替代实际 UI 验收。

## Risks / Trade-offs

- [上游 API 与本地参考版本可能不同] → 实施时固定并核对原始上游版本，记录实际版本，不修改 MyGo。
- [开发启动可能首次下载原生库，网络失败会阻止启动] → 文档说明依赖获取条件，失败时保留实际错误；打包发布不在本轮范围。
- [Shell 退出与窗口关闭可能交错] → 保护初始化时序和重复清理，并覆盖对应生命周期测试。
- [GUI 测试需要桌面会话] → 使用真实桌面执行验收并记录结果；无法执行时明确标记未验收。
- [用户 Shell 配置可能影响启动与提示符] → 验收依据具体命令输出，不匹配固定提示符字符串。
- [终端关闭不保证结束用户主动脱离会话的后台进程] → 本轮只管理应用直接拥有的终端与 Shell，不实现进程树管理。

## Migration Plan

本项目为首次引入应用，无数据迁移。实现完成后通过 `go run ./cmd/whos-typing` 启动验收；回退时移除本次新增应用文件和依赖，不涉及用户数据变更。
