# Design

## Context

动机和范围见 proposal.md。规划时 worktree 基于 `7f95c13`；实施前已 rebase 到 `b8f79df`，保留 master 已提交的远端恢复修复。现有 `workspaceView` 将标签栏放在内容区上方；`workspace` 使用 16 字节随机数的十六进制字符串作为 ID，并以 `nextTab` 生成数字标题。`pane` 独立持有终端和控制视图，适合保存搜索状态。

现有规格要求会话 ID 在关闭及重启后不复用，标签默认名不受 Shell OSC 标题影响。此次保留前者，将后者改为动态默认标题与人工标题分离。Shell 的本地提示符和远端 Bash 协议已有带会话令牌的控制标记，但尚未提供完整的用户、主机和目录元信息。

已在用户指定的本地 MyGo `48da1ba` 阅读 `plugins/terminal/search.go`、搜索测试和 `docs/ui/windows.md`。搜索接口包括 `Search`、`SearchNext`、`SearchPrevious`、`EndSearch`、`SearchStatus` 和 `Options.OnSearch`；标题栏接口包括 `TitleBarHidden`、`Context.TitleBar` 和 `DragWindow`。实施核验确认固定版本 `v0.7.4` 已包含这些接口；配套原生库和上游搜索测试均通过，保持依赖版本不变。

## Goals / Non-Goals

**Goals:**

- 复用终端原有缓冲区、坐标和高亮实现，搜索 UI 与 Shell 输入分离。
- 以稳定短 ID 寻址，以标签数组顺序解释快捷键，以会话元信息生成默认标题，三者互不替代。
- 保持入口和视图层只做编排，将标识分配、标题格式化和搜索状态放入独立模块。

**Non-Goals:**

- 不维护第二份终端日志，不以 `session read` 的截断文本构建搜索索引。
- 不搜索隐藏标签或其他窗格，不增加正则、大小写开关、历史归档、标签拖动排序或快捷键配置。
- 不为标题查询主动向正在运行的 SSH、密码提示或交互程序发送命令。

## Decisions

### 1. 搜索状态归属窗格

每个 pane 保存搜索词、打开状态、搜索结果状态和输入框聚焦请求。工作区在 Shell 输入前处理 `Cmd+F`，捕获当前窗格后聚焦其搜索框。输入变化调用 `Search`，`OnSearch` 只更新该窗格的 UI 状态，不重新获取工作区锁，避免视图持锁调用终端时发生重入死锁。

使用输入框内 `Enter`、`Shift+Enter`，以及搜索打开时的 `Cmd+G`、`Cmd+Shift+G` 导航。沿用上游方向：下一项指向更早输出，上一项指向更新输出。首次选择最新匹配，结果循环。`Searching` 为真时显示搜索中状态，完成且总数为零时显示无结果。

在窗格内部为搜索栏分配独立顶部行，终端控制胶囊仍位于下方终端区域，避免两者覆盖。搜索栏出现会缩小终端区域，必须验证自动换行及 resize 后匹配位置。关闭时调用 `EndSearch`、移除高亮并恢复该窗格终端焦点；保留搜索词但不自动恢复到输出底部。切换窗格时关闭原窗格搜索 UI 和高亮、保留词，不将词复制到新窗格。再次打开时重新搜索。关闭窗格释放状态。

采用上游字面匹配规则，仅忽略 ASCII 字母大小写。搜索推进依赖可见视图帧，单帧约 4 ms 的扫描预算由上游控制。不另开线程扫描 Text()，避免缓冲区位置和显示网格不一致。

### 2. 标题栏统一布局

窗口使用隐藏标题栏但保留系统按钮的模式。布局读取 `Context.TitleBar()` 的 Left、Right、Height，不硬编码红绿灯坐标；全屏时按实际占位重新计算。仅在标题栏空白区允许拖动窗口，标签点击及菜单操作不触发拖动。

一个标签时绘制普通标题，不绘制标签边框或选中背景，并保留右键关闭菜单。多个标签时在按钮占位以外按 N 等宽排列，窄窗口仍等宽收缩，以省略文本和完整 tooltip 保持可用，不恢复横向滚动按钮或第二行。多标签不再采用之前探索中提议的横向溢出方案。

标题不含内部 ID 或位置前缀。`Cmd+1` 至 `Cmd+9` 查当前数组下标；`Cmd+9` 就是第九个，不特殊映射为最后一个。不存在的位置无操作。超过九个标签仍可点击切换。新标签追加，关闭只移除该项，不重新分配 ID。

### 3. 默认标题来自结构化元信息

标签保存可选人工标题；未重命名时，使用该标签最后选中窗格的结构化元信息生成 `username@hostname:/path`。GUI 和 CLI 的 `tab_title` 调用同一格式化逻辑。人工标题保持至标签关闭，不被工作目录、焦点或 OSC 标题覆盖；本次不新增恢复自动标题命令。

本地 Shell 初始化提供启动时的用户、主机和实际工作目录，并在已有 zsh、bash、fish 提示符钩子上报变化。远端只在用户完成现有 Bash 接入流程后通过同一机制上报。给元信息定义带现有随机协议令牌的标记，字段必须编码并设长度上限，解析器处理拆包、非法内容和包含换行的路径；不得直接以换行或冒号拆分未编码字段。渲染前将控制字符转换为可见转义，不允许污染终端或标题布局。

元信息解析和状态通知属于 shell 包，标题格式化属于 app 包，更新通过窗口 UI 调度。标记沿用控制输出过滤规则，不进入命令输出或搜索内容，不改变保存的命令退出码、提示符就绪状态或控制权。协议认证令牌不属于用户操作 ID，保持现有强度，不缩短。

未收到元信息时使用启动本地上下文；不能可靠识别的未接入远端不承诺实时远端身份，保留最后确认值。已接入远端失联且未确认返回本地时，保留最后确认值并标注状态未知；重新收到本地提示符元信息后切回本地。错误或缺失元信息不得阻塞命令或触发探测输入。

### 4. 独立序列标识保留跨重启防复用

会话和标签使用两个独立的十进制递增序列，分别生成 `session_01`、`session_02` 和 `tab_01`、`tab_02`。数字部分至少两位，超过 99 后自然增长，例如 `session_100`、`tab_100`。分屏只分配会话 ID，不分配标签 ID。ID 与显示位置无关，创建失败允许留下编号空洞。分屏布局内部节点可使用内部键，不对 Agent 暴露，也不改变 Shell 协议令牌。

在 `os.UserConfigDir()` 下的 `whos-typing/id-sequences` 文件中持久化两组已分配高水位，目录权限为 0700、文件权限为 0600；不使用可能被系统清理的 `/tmp` 控制目录，复用服务单实例锁串行分配。先原子持久化递增值，再向工作区和调用者发布 ID；写入使用临时文件、同步和原子替换，并检查错误。重启继续分配，失败不回退到零；状态损坏、存储失败或对应序列耗尽时拒绝创建并返回明确错误。写入结果不确定时，本进程停止两组序列的分配。高水位文件不随 socket 清理或应用退出删除。首次安装可创建初始状态；删除应用数据后的跨安装身份连续性不在本次承诺内。

持久化计数用于满足跨重启不复用约束。此存储仅保存计数，不保存终端输出。顺序 ID 不作为访问凭证，继续依赖私有目录和 socket 权限。未发布的 8 位方案使用旧 `id-high-water` 文件；由于旧 ID 与新 ID 的前缀不同，新序列可从 01 开始。新程序不读取或覆盖旧文件，也不把旧 ID 映射到新会话。

CLI 保持把目标当作不透明字符串转发，服务精确查找完整 ID，不增加唯一前缀、位置别名或未知 ID 回退。新服务返回短 ID；新 CLI 连接仍存活的旧版多会话 GUI 时继续使用其返回的完整长 ID，不截断或强制限制输入格式和长度。升级重启后的旧会话本来就已结束，旧长 ID 应报不存在，不建立替换映射。保留已有协议能力握手与单会话省略目标行为。

### 5. 依赖采用原始上游版本

已验证固定版本 `v0.7.4` 的上述接口及配套 libghostty-vt，保持依赖版本不变。不使用本地 replace、fork 或自行复制终端搜索实现。

## Risks / Trade-offs

- 窗口按钮区域和全屏尺寸不同：用框架占位信息布局，并分别验收普通、全屏、窄窗口和多标签。
- 高频输出、历史淘汰、替代屏幕和中文宽字符影响搜索：复用上游坐标，高亮与计数变化通过隔离终端测试验证，不保证已淘汰内容可搜。
- 现有工作区锁与 UI 回调可能死锁：回调只更新 UI 所有的搜索状态，避免嵌套获取 workspace 锁，补充切换和关闭竞态测试。
- 短 ID 状态文件增加持久化依赖：在用户持久状态目录中只保存高水位，故障明确拒绝创建，不通过重置状态恢复。
- 未接入的 SSH 不能可靠提供身份和目录：明确保留最后确认上下文，不解析任意提示符猜测信息；只对完成接入的远端提供更新保证。
- 基线包含远端恢复修复：实施前已 rebase 到 `b8f79df`，元信息处理保留其恢复逻辑，并补充确认边界测试。

## Migration Plan

1. 在独立 worktree 完成依赖核验和隔离测试，再接入应用 UI 与元信息；不使用用户正在运行的 GUI 或 SSH 验证。
2. 更新 CLI 帮助、Skill 和开发文档，说明 ID 有类型前缀及独立递增序号，且必须原样使用完整标识，快捷键按位置，默认标题可变化。GUI 和 CLI 一起发布，兼容测试覆盖新旧多会话协议。
3. 回滚应用版本时保留高水位文件；旧版忽略新文件并继续生成原格式 ID。再次升级读取两组已保存高水位，不重新使用新格式 ID。回滚和升级均不迁移已退出的 Shell 会话。
