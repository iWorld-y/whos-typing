# Design

## Context

动机和范围见 proposal.md。当前 `internal/app/app.go` 在启动时创建一个 `shell.Session`、一个 `terminal.Terminal` 和一个窗口。`internal/app/session.go` 将 Shell 退出直接映射为窗口关闭，`internal/control/control.go` 将所有请求交给同一个 executor，协议没有会话目标。现有 `session_test.go` 也按单会话退出整个窗口验收。

`shell.Session` 已独立持有 PTY、命令状态、控制权计时和远端连接，可复用到每个窗格。MyGo v0.7.4 提供 Tabs/TabsBase、SplitPercent、SplitVerticalPercent 和可聚焦终端视图，终端读取循环独立于视图绘制。源码具备组合基础，但隐藏标签页、嵌套布局下的焦点、终端尺寸和性能仍需隔离运行验证。

现有规格中“窗口期间复用同一个 Shell”和“任意 Shell 退出即退出应用”不适用于多会话，已在 local-terminal 增量中调整。其余终端输入、快照截断和远端结果未知规则继续保留。

## Goals / Non-Goals

**Goals:**

- 将工作区布局与会话资源生命周期分开，使同一套操作供 GUI 和 CLI 调用。
- 使用稳定目标保证请求不会随焦点切换而改变，并保持单会话调用兼容。
- 保留单实例 socket、用户私有目录和既有 Shell 输入保护。

**Non-Goals:**

- 不引入后台守护进程、会话持久化或多窗口路由。
- 不复制现有 Shell 的环境修改、运行中程序或远端 SSH 连接。新会话沿用当前启动本地登录 Shell 的行为及初始目录。
- 不新增 CLI 关闭会话或关闭标签页命令；本次关闭入口在 GUI，Shell 自行退出仍有效。

## Decisions

### 工作区使用标签页列表和二叉分屏树

工作区持有有序标签页、选中标签页 ID 及会话注册表。标签页持有布局根节点、最近聚焦会话 ID 和标签页名称。应用内的成功创建顺序从 1 开始递增，默认名称至少保留两位数字；关闭标签页不改变或复用已分配编号。序号只在新标签页成功登记时递增，创建失败或分屏不消耗编号；超过 99 后继续显示 100 等完整数字。重命名只修改显示名称，不改变编号分配、tab_id 或该页各 session_id。名称仅保留到应用退出。叶节点关联一个会话 ID，分支节点保存左右或上下方向、比例及两个子节点。

分屏将目标叶节点替换为一个分支，原会话在左侧或上方，新会话在右侧或下方。比例初始为 50%，后续由用户拖动。关闭叶节点时以其兄弟子树替换父节点；焦点移到兄弟子树的第一个存活叶节点。关闭当前标签页时选中右侧相邻标签页，没有则选择左侧；最后一个会话关闭后退出。

选择树结构是为了自然表达示例中的递归分屏。固定网格无法表达任意窗格再次分屏，存储绝对坐标则需要自行处理缩放和布局约束。稳定随机 ID 用于会话和标签页，不能使用数组下标，也不能复用 Shell 内部用于协议校验的 token。

### 创建与关闭由工作区协调，资源操作放在会话层

应用入口只负责启动服务、窗口和工作区。会话创建函数负责 Shell、终端和回调绑定，工作区负责登记与布局提交。GUI 和 CLI 调用相同的创建、分屏和聚焦操作，避免行为分叉。

创建先分配并确认资源可用，再持工作区锁提交布局，并通知窗口刷新。UI 读取工作区状态时使用同一把锁。MyGo 分隔线事件只修改 UI 线程持有的临时比例，下一次构建时持锁同步到布局，避免输入回调直接修改共享节点。创建请求不等待窗口线程。提交前复查目标仍存活；失败或目标已关闭时回收资源，保留原布局和焦点。关闭先将会话标为不可寻址并移除布局，再在不持有工作区锁的情况下结束连接、取消等待并释放终端，避免与 OnExit 回调互相等待。

会话自行退出只通知工作区删除对应叶节点。只有关闭整个窗口或工作区已无会话时才退出应用。使用实例身份检查丢弃已关闭会话的迟到回调。

### 焦点与命令目标分开维护

`session current` 表示最后选中的终端，不要求窗口此刻在前台。标签栏控件、弹窗和切到 Codex 不清空该选择，另返回 `window_focused`。切换标签页恢复该页最近的存活焦点，点击终端或显式聚焦会更新记录。

GUI 新建自动选中新会话。CLI 创建默认不激活窗口、不改变选中标签页或终端焦点；`--focus` 和 `session focus` 切换并激活目标窗格。后台创建会话必须启动 Shell 并提供 CLI 操作能力，不能等首次显示后才初始化。

不让省略 `--session` 等价于当前焦点。Agent 理解“这个会话”时先调用 current，将返回的 ID 绑定到整组操作。查询后用户改变焦点不会改变该组操作的目标。

### CLI 语法和发现结果

保留现有直接传命令字符串的形式，不另加 exec 子命令。`--session` 作为顶层选项统一解析并与现有 `--timeout` 组合；`--` 可明确结束选项解析。

```sh
whos-typing-cli session list --json
whos-typing-cli session current --json
whos-typing-cli tab new --json
whos-typing-cli tab rename --tab <tab_id> '标题'
whos-typing-cli --session <id> session split --direction right --json
whos-typing-cli --session <id> session split --direction down --focus --json
whos-typing-cli --session <id> session focus
whos-typing-cli --session <id> --timeout 30s 'pwd'
whos-typing-cli --session <id> session read
whos-typing-cli --session <id> session status
whos-typing-cli --session <id> session release
whos-typing-cli --session <id> attach --remote --shell bash --auto
```

列表 JSON 包含 sessions 数组、当前 session_id 和 window_focused；数组条目含 session_id、tab_id、tab_title、title、control。current 返回单个条目的同类字段及 window_focused。标签名与 Shell 的 title 独立，`tab rename` 只接受稳定 tab_id 和非空白标题，不改变焦点。创建 JSON 返回新 session_id 和 tab_id。Shell 未报告 title 时使用终端默认名称，标签栏始终显示独立的 tab_title。现有 session status 的控制方文本、session read 快照和执行原始输出不包进新的 JSON，以免破坏现有消费方式。

目标解析在服务端完成并与注册表状态读取保持原子性。指定 ID 时精确查找；未指定且仅一个存活会话时绑定它；零个或多个时返回错误。执行期间持有目标会话引用，不持有工作区全局锁，不在发送时重新查当前焦点。单会话兼容同样只解析一次，随后新增会话不会改变已绑定请求。

### 新协议必须防止旧服务忽略目标字段

旧服务的 JSON 解码会忽略未知字段，仅给旧请求增加 session_id 不安全。新增非执行握手 action，先在同一连接确认服务协议版本及多会话能力，再提交带目标的操作；握手未知或断开时拒绝操作，不发送命令正文，不降级重试。

新版服务接受握手后的一次操作，同时保留无握手旧请求入口。旧请求仅能通过服务端单会话解析规则。保留既有流式结果、超时与客户端断连取消逻辑。创建响应丢失不能被当成创建失败并自动重试，调用者应通过列表核对。

相比独立连接上的版本查询，同连接握手避免查询后 GUI 重启成旧版本的竞态。创建、发现和聚焦 action 使用明确动作名称，不能误落入命令执行路径。

### GUI 快捷键与关闭入口

窗口移除新建、分屏和关闭操作按钮栏，仅保留标签栏及必要的标签滚动入口。`Cmd+T` 创建标签页，`Cmd+D` 将当前窗格向右分屏，`Cmd+Shift+D` 将当前窗格向下分屏；两种分屏均保留原窗格在左侧或上方。操作成功后聚焦新会话。

快捷键在 Shell 输入处理之前消费，因此 Agent 持有控制权时仍可新建标签或分屏。快捷键不得进入 PTY、改写原窗格的未提交输入或切换原会话控制权。仅注册上述三个组合，不附加其他快捷键。

标签页右键菜单提供关闭该标签页和关闭该页最后选中窗格的入口。右键操作按被点击的标签页 ID 绑定目标，不能误关闭另一标签页的当前窗格；终端自身右键菜单保持可用。

### 终端视图和控制状态按会话隔离

每个会话持有独立控制视图，使用会话 ID 建立稳定 UI key 作用域。递归渲染分屏时复用 Terminal 实例，不在每帧或切换标签页时重建。只对显式焦点变化调用聚焦，不能给每个视图持续 AutoFocus。

胶囊尺寸以窗格而非窗口为基准，光效和玻璃区域裁剪在窗格内。隐藏标签页仍读取输出并维护控制计时，只绘制当前标签页。验证隐藏终端的失焦事件、输入法组合状态及后台输出引发的重绘；不能以暂停 PTY 读取降低后台开销。

自动接入确认携带目标 session_id 和 tab_id。沿用单个可见确认对话框，忙时拒绝额外确认请求，避免堆叠；对话框提供查看目标入口，用户主动查看才切换焦点。发送前仍由绑定 Shell 执行空提示符和控制权检查。目标关闭会取消其确认，不影响其他会话。

## Risks / Trade-offs

- 隐藏终端可能继续触发窗口重绘。通过隔离 GUI 验收测量，先确保输出持续正确，若出现无效重绘再限制可见视图刷新。
- 深层分屏可能使胶囊和终端过窄。沿用分隔线约束并限制控件在窗格内，验收最窄可操作尺寸和窗口缩放，不承诺无限可用分屏数量。
- 关闭与创建、执行、远端确认可能并发。通过注册表状态、一次性关闭和会话实例检查保证操作不改投其他会话。
- 单个失效会话不应阻塞服务关闭或其他会话。扩展现有断连、未读输出和重复关闭测试，并运行 race 检查。
- 多会话改变旧命令的省略目标行为。帮助与内置 Skill 明确先发现、再绑定 ID，GUI 与 CLI 一起发布。

## Migration Plan

实现先建立会话与布局模型，再接入路由及 GUI，最后更新 CLI 帮助、内置 Skill 和使用文档。用独立进程与临时 socket 验收，不操作用户正在使用的终端。

无持久数据迁移。发布时同时替换 GUI 和 CLI；运行中的旧 GUI 会被新版 CLI 明确拒绝目标操作。回退时关闭测试实例后成套恢复旧 GUI 与 CLI；运行中的会话不能迁移或恢复，不能通过自动重启用户窗口完成回退。
