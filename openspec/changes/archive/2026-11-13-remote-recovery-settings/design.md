# Design

## Context

动机见 `proposal.md`。基线为 `c1500d8`。`remoteCommand` 在同一个交互式 Bash 中执行 `eval`，完成后才发送结束标记；接入脚本只安装提示符钩子，没有 Shell 退出通知。`Execute` 超时后保留未知请求，`canRecoverRemote` 拒绝活动请求、孤立请求及未知集合。现有退出测试返回带标记的本地 Shell，未覆盖 SSH 内嵌套 Bash 退出。

本轮已编译并运行六项现有定向测试，全部通过；独立 Bash 实验确认 `set -e` 跨命令保留并可跳过结束标记。尚未新增端到端复现测试。应用目前没有设置页，已有用户配置目录仅用于稳定 ID 序列。

## Goals / Non-Goals

**Goals:**
- 将接入生命周期和命令结果分开，避免未知结果永久阻塞恢复。
- 用户可以选择自动批准首次接入，同时保留输入队列及会话边界。
- 通过独立 Shell、临时 socket 和项目构建程序完成验收。

**Non-Goals:**
- 不替换共享 Shell 为每次命令独立进程，不自动撤销用户的 Shell 选项。
- 不推断业务操作是否成功，不重放或自动终止未知命令。
- 不修改安装版 App、用户正在使用的 SSH 或任何构建服务器。

## Decisions

### 1. 退出通知与未知结果分别处理

在接入 Bash 中添加按接入标识命名的 `EXIT` 通知，携带 Shell 身份与退出状态。使用 Bash 进程身份区分本体和子 Shell，不能只依赖在子 Shell 中保持不变的 `$$`。保留已有 `EXIT` trap 的执行及 `$?` 语义，不覆盖用户行为；旧钩子恢复和清理仅处理本应用安装的内容。用户后来改写 trap、`exec` 或不可捕获的退出仍可能没有通知，因此退出通知不是唯一恢复条件。

收到有效通知时，只结束属于该接入的等待请求，并标为接入丢失；未收到结束标记则保留结果未知。不要把退出通知当作提示符就绪。保留现有本地提示符识别，二者共用请求收尾规则，避免重复完成。

不选择给 `eval` 包上 `if`、`||` 或强制 `set +e`：这些做法可能改变用户脚本的 errexit 行为。也不通过正则识别 `[dev@host]$`，因为普通程序可以输出相同文本。

### 2. 显式恢复独立于普通接入

扩展现有 GUI 恢复操作，而非让 `attach` 或 `release` 无条件清空未知请求。用户接管后可看到“恢复远端接入”，并确认目标、空提示符和旧结果未知。自动允许设置不跳过这一确认。

恢复操作在锁内绑定目标与旧接入代次，取消未发送请求，等待或拒绝尚未完成的输入注入。确认期间保持现有输入计数、输出变化、进程组检查。确认通过后将旧等待请求结束为“等待已放弃，结果未知”，解除其对新接入的阻塞，但保留诊断信息。新握手失败时保持人类控制，并允许重试恢复；不得回滚成旧接入已就绪。

旧代次标记只可用于旧请求的清理，不能改变新接入或新请求状态。不把超时等同于命令结束，也不自动发送 Ctrl+C。

### 3. 设置窗口与偏好文件

采用一个小型设置窗口，只提供本次自动接入开关，通过工作区可见设置按钮打开，已有窗口重复打开时聚焦。保持 UI 编排与配置读写分离。设置文件放在 `os.UserConfigDir()/whos-typing/settings.json`，使用独立模块加载和原子保存，不混入 `id-sequences`。文件仅保存偏好，不保存终端文本或凭据。

方案默认值为关闭，兼容现有行为；用户开启后对后续请求立即生效，应用重启后保留。写入成功后再更新有效值，失败时提示并回退 UI。配置损坏时保留文件、提示错误并采用关闭值。

### 4. 自动批准不改变协议握手

在应用接入协调层读取申请开始时的偏好。关闭时调用已有确认框；开启时直接进入同一排队、变化检查和握手路径，不另写一条绕过保护的输入通道。手动复制接入命令的方式保留。已经打开的确认框沿用原审批流程，避免设置切换自动批准旧申请。

首次接入前，应用并不能仅靠本地 PTY 前台进程组可靠识别远端的密码提示或服务器身份。开启自动允许表示用户授权跳过这次人工核对，调用方仍须确保已进入目标 Bash；文案和技能不能承诺能够自动识别所有远端交互程序。可检测的人类接管、输入、输出变化与进程组变化仍必须拒绝。

### 5. 保持 CLI 兼容并提供可操作诊断

保留 `session status` 的现有文本控制方输出，新增 `session status --json` 返回控制方、接入状态、未知结果及建议动作。扩展为可选响应字段，不要求旧 GUI 伪造不存在的恢复能力；新 CLI 连接旧 GUI 时明确表示诊断字段不可用。状态查询只读，错误消息指向 GUI 恢复入口，不建议用户反复执行一定会失败的普通 attach。

## Risks / Trade-offs

- EXIT trap 的 Bash 版本与继承语义不同：使用项目现有隔离夹具覆盖内层退出、子 Shell、已有 trap、trap 被覆盖及重复清理；无法收到通知时仍提供人工恢复。
- 自动允许无法判断所有远端登录状态：默认关闭、明确作用说明，保留现有可检测保护和独立目标标识。
- 恢复与发送并发：只有在发送边界稳定后才允许新握手，测试覆盖排队取消、写入未结束、旧标记迟到和目标关闭。
- 不完整结果不会因为恢复而变完整：UI 与 CLI 始终保留“结果未知”，业务重试由调用方核对后决定。

## Migration Plan

新版本首次启动保持自动允许关闭，不迁移 ID 文件，不改现有终端配置。开发与验收仅从本 worktree 编译，使用临时配置和 socket。验收完成前不安装或替换 DMG App。关闭开关即可恢复逐次接入确认；回退程序时偏好文件保留，不依赖新字段完成旧版启动。
