# Spec Delta

## MODIFIED Requirements

### Requirement: 自动接入确认明确绑定会话

自动远端接入 SHALL 始终绑定目标会话及标签页。自动允许关闭时，确认 SHALL 标明目标会话 ID 和标签页，用户 SHALL 能查看目标窗格后确认；自动允许开启时，首次接入 SHALL 无需确认框。焦点变化不得替换目标，目标关闭或请求取消 SHALL 使申请失效。两种模式 SHALL 保留控制权、人工输入、前台进程组及申请期间终端变化检查，新握手完成前不得执行业务命令。

#### Scenario: 确认过程中切换焦点
- **WHEN** 自动接入请求绑定 A，用户在确认前切换到 B
- **THEN** 确认仍明确指向 A，只能向 A 发送接入输入
- **AND** 发送前重新检查 A 的空提示符和控制权，不向 B 注入输入

#### Scenario: 确认目标已关闭
- **WHEN** A 的接入确认尚未完成而 A 被关闭
- **THEN** 请求结束并提示目标不可用，旧确认不能作用于新会话

#### Scenario: 自动允许首次接入
- **WHEN** 自动允许已开启，用户已在 A 登录目标交互式 Bash，CLI 发起自动接入且现有输入及进程组检查通过
- **THEN** 仅向 A 发送一次接入命令，不弹出确认框
- **AND** 只有握手成功后才允许执行命令

#### Scenario: 自动允许不能覆盖保护条件
- **WHEN** 自动允许已开启，但用户主动接管、存在未提交输入，或接入期间终端输入、输出、前台进程组发生变化
- **THEN** 接入被拒绝，不修改人工输入，不向其他会话发送命令

## ADDED Requirements

### Requirement: 接入 Shell 退出通知

系统 SHALL 在收到当前接入 Shell 的有效退出通知时使该接入失效，并结束等待中的 CLI 请求，不等待其原超时耗尽。缺少命令完成证据时 SHALL 报告结果未知，不将 Shell 退出码当作完整业务命令结果。系统 SHALL 不将普通提示符文本或子 Shell 退出当作有效退出通知。

#### Scenario: 内层 Bash 因 errexit 退出
- **WHEN** 接入的内层 Bash 保留了 `set -e`，后续失败命令使其退出并发出有效退出通知，SSH 内的外层 Bash 仍然存活
- **THEN** 等待中的 CLI 收到接入已失效、命令结果未知的错误
- **AND** 当前窗格和 SSH 保留，用户获得可操作的恢复提示

#### Scenario: 命令启动子 Shell
- **WHEN** 业务命令中的子 Shell 退出，但接入的 Bash 仍然存活
- **THEN** 接入保持有效，不因子 Shell 的退出而终止当前请求

#### Scenario: 退出钩子不可用
- **WHEN** 钩子被覆盖或 Shell 异常终止，系统无法获取可信完成或退出通知
- **THEN** 保留结果未知的状态，允许用户发起失效绑定恢复，不自动推断命令已停止

### Requirement: 用户确认后恢复失效绑定

系统 SHALL 在用户主动接管后提供恢复失效绑定的入口，包括旧 CLI 仍在等待、超时或取消后结果未知的情况。恢复 SHALL 要求用户明确确认目标 Bash 空提示符及放弃旧请求等待，即使自动允许设置已开启。确认后 SHALL 保留旧结果未知的记录，作废旧绑定并建立新握手，不重放旧命令、不关闭 SSH、不向旧命令发送终止信号。未完成的输入和仍在发送的命令字节 SHALL 阻止接入注入。

#### Scenario: 超时或取消后恢复
- **WHEN** 用户确认旧接入已失效、当前为目标 Bash 空提示符，并发起恢复
- **THEN** 旧请求不再阻塞新握手，原结果仍标为未知
- **AND** 新握手完成后恢复同一窗格的 Agent 控制，无需新开会话

#### Scenario: CLI 仍等待旧请求
- **WHEN** 旧 CLI 仍在等待，用户确认恢复且旧输入发送已经结束
- **THEN** 旧 CLI 收到等待已放弃、结果未知的错误，新接入使用独立标识

#### Scenario: 取消恢复或状态改变
- **WHEN** 用户取消恢复，或确认期间发生新输入、输出、前台进程变化或目标关闭
- **THEN** 不注入接入命令，保留人类控制和未知结果，并允许以后再次申请恢复

#### Scenario: 旧通知迟到
- **WHEN** 恢复后收到旧接入的完成或提示符通知
- **THEN** 通知不能完成新请求、改变新控制状态或开放新接入

### Requirement: 提供一致的状态诊断

CLI SHALL 提供包含控制方、接入状态、是否存在未知结果和建议动作的结构化状态查询，同时保留现有 `session status` 文本输出兼容性。执行、接入和交还失败提示 SHALL 指向实际可用的恢复入口，仅读取状态不得获取控制权。

#### Scenario: 旧请求未知时查询
- **WHEN** 旧请求结果未知且普通执行被拒绝，调用结构化状态查询
- **THEN** 返回未知结果及用户接管后恢复失效绑定的动作，不只返回 `agent`
- **AND** 普通接入与交还错误给出一致的恢复说明
