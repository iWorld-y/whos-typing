# Spec Delta

## Purpose

让用户和 Agent 在同一个受管 SSH 会话中连续执行命令，保留远端 Bash 的工作目录和环境。工作区在命令运行期间显示实际终端输出，并允许用户接管当前前台程序。

## ADDED Requirements

### Requirement: 显式创建受管 SSH 会话

应用 SHALL 提供显式创建入口，使用已有的 OpenSSH 目标和认证配置，在工作区创建独立标签页及远端 Bash。成功 SHALL 返回可寻址的会话和标签页 ID。身份验证、连接或会话启动失败时 SHALL 报告原因，释放本次创建的资源，保留原有窗格及其内容。

#### Scenario: 创建后通过 CLI 执行
- **WHEN** 运行中的应用收到创建受管 SSH 会话的请求，指定目标的 SSH 连接可用且远端 Bash 已就绪
- **THEN** 受管 SSH 标签页显示目标，CLI 可以用返回的完整会话 ID 执行命令
- **AND** 创建操作本身不获取 Agent 控制权

#### Scenario: 启动失败
- **WHEN** 连接不可用、主机身份验证失败或远端执行组件无法启动
- **THEN** 请求失败，系统不留下空标签页，也不切换到本地 Shell 或未经验证的远端连接

### Requirement: 同一 Bash 保留目录和环境

系统 SHALL 在一个受管 SSH 会话内使用同一个远端 Bash 执行连续命令。该 Bash 中生效的目录切换及环境修改 SHALL 对后续命令可见。各窗格 SHALL 使用独立 Bash，即使它们复用同一条 SSH 连接。

#### Scenario: 多次 CLI 调用沿用状态
- **WHEN** Agent 在同一会话中分别提交成功的 `cd /srv/app`、`export WT_TEST=ready` 和 `source .venv/bin/activate`
- **THEN** 后续独立调用中的 `pwd` 与环境查询反映前面命令的修改，无需重复设置目录或环境

#### Scenario: 同目标的窗格相互独立
- **WHEN** A、B 使用同一个 SSH 目标，且 Agent 在 A 切换目录或设置环境
- **THEN** A 的改变不会影响 B，也不会因切换标签页而丢失

### Requirement: 命令请求与前台输入分离

受管 SSH 会话 SHALL 通过独立于终端键盘输入的通道接收 CLI 命令。CLI 命令 SHALL 仅在对应 Bash 就绪时启动。同一会话存在未完成命令、人工输入或正在被用户接管时，系统 SHALL 明确拒绝新命令，且不得在稍后自动执行。

#### Scenario: 前台程序等待输入
- **WHEN** Agent 启动的 `vim`、`less` 或子 Shell 仍占用前台，CLI 请求执行下一条命令
- **THEN** CLI 收到当前会话忙或由人类控制的反馈，待执行文本不进入前台程序
- **AND** 用户退出前台程序并恢复 Agent 控制后，可以重新提交该命令

#### Scenario: 提示符外观改变
- **WHEN** Bash 的提示符内容变化，且执行后端确认没有未提交输入或运行中的命令
- **THEN** CLI 仍可执行，系统不靠提示符文本或终端回显判定 Bash 是否就绪

### Requirement: 显示一次执行的命令和输出

GUI SHALL 显示实际提交的命令文本，并在执行期间显示同一次执行的终端输出。系统 SHALL 使用可信的完成通知报告命令退出状态。CLI SHALL 保留现有命令输出和退出状态的返回方式。切换标签页或更改窗格尺寸 SHALL 不改变命令、执行会话或输入目标。

#### Scenario: 长命令逐步输出
- **WHEN** 远端程序先输出一行，再等待并输出第二行
- **THEN** GUI 在程序结束前显示第一行，随后显示第二行及最终退出状态
- **AND** CLI 获得该次执行的输出和退出状态

#### Scenario: 终端程序输出类似控制通知的文本
- **WHEN** 命令在终端输出中打印了看起来像完成通知的文本
- **THEN** GUI 将该文本作为输出显示，执行状态仍由后端的完成通知决定

### Requirement: 接管同一个远端前台程序

接管 SHALL 切换当前受管会话的输入权，并保持正在运行的程序。用户的键盘及 `Ctrl+C` SHALL 发往同一个远端前台终端。程序退出后，用户 SHALL 能在原 Bash 继续操作或在就绪后交还 Agent。接管动作本身 SHALL 不发送中断。

#### Scenario: 接管编辑器后继续执行
- **WHEN** Agent 打开的 `vim` 正在运行，用户点击「接管」并在当前编辑器中完成操作后退出
- **THEN** 用户操作的是原编辑器，退出后仍使用原 Bash
- **AND** 用户交还后，下一条 Agent 命令沿用此前的目录和环境

#### Scenario: 中断可响应 Ctrl+C 的前台命令
- **WHEN** 用户对当前窗格的 `sleep` 按下 `Ctrl+C`
- **THEN** 只有该窗格的前台命令响应中断
- **AND** 系统根据实际完成通知报告退出状态，原 Bash 仍可执行后续命令

### Requirement: 区分拒绝、完成和未知结果

系统 SHALL 区分已确认未执行、已确认完成和结果未知。CLI 等待超时或断开 SHALL 不被视为命令结束。如果后端仍连接远端，系统 SHALL 继续展示输出并追踪命令，直至收到可信完成通知。失去远端会话且无法确认结果时 SHALL 报告结果未知，不自动重放命令或恢复 Shell 状态。

#### Scenario: CLI 超时而远端仍运行
- **WHEN** CLI 等待超时，但应用仍连接受管 Bash，且后端尚未收到完成通知
- **THEN** CLI 报告结果未知，GUI 继续显示输出并允许用户接管当前程序
- **AND** 系统不因这次超时开放同一 Bash 执行下一条命令

#### Scenario: 执行中 SSH 断开
- **WHEN** SSH 连接丢失且命令没有可信完成通知
- **THEN** 系统报告结果未知，结束受管会话，并提示显式新建会话
- **AND** 旧会话的目录、环境及等待中的请求不转移到新会话

### Requirement: 关闭只释放对应受管会话

关闭受管窗格 SHALL 释放对应远端执行会话和本地订阅。关闭单个窗格 SHALL 不关闭仍由其他窗格使用的 SSH 复用连接。主动退出应用结束由应用持有的受管会话，重启后 SHALL 不自动重建会话或重放请求。

#### Scenario: 两个窗格复用连接时关闭其中一个
- **WHEN** A、B 连接同一个 SSH 目标，用户关闭 A
- **THEN** A 的资源被释放，B 的命令、输入控制权和目录保持原状
