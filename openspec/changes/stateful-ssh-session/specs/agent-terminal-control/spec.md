# Spec Delta

## MODIFIED Requirements

### Requirement: CLI 操作获取 Agent 控制权

系统 SHALL 将通过 CLI 向终端发送执行命令或自动接入输入视为 Agent 操作，并在会话可以安全执行且未被用户主动接管时给予 Agent 控制权。共享 Shell 依据空提示符和输入状态判定。受管 SSH 会话依据后端报告的 Bash 就绪状态及人工输入判定。人工运行 CLI 使用相同行为。控制权变化 SHALL 仅作用于请求绑定的会话。

#### Scenario: CLI 在空闲终端执行命令
- **WHEN** 用户未主动接管，终端停在可接收命令的空提示符，CLI 发起执行请求
- **THEN** 系统切换到 Agent 控制状态并执行该命令
- **AND** 请求按会话路由规则确定目标，原有命令输出和退出状态行为保持可用

#### Scenario: 人类已有未提交输入
- **WHEN** 人类已有未提交输入，CLI 发起执行请求
- **THEN** 系统拒绝请求并保留人类输入
- **AND** 系统不得为了接管而提交、清除或覆盖这些输入

#### Scenario: 只读请求不获取控制权
- **WHEN** CLI 调用 `session read` 读取终端快照
- **THEN** 系统返回快照，不因读取而切换控制权
- **AND** 读取不重置 Agent 的空闲计时

#### Scenario: 受管 Bash 就绪时通过 CLI 执行
- **WHEN** 用户未主动接管，受管 SSH 会话的 Bash 已就绪且没有未提交的人工输入
- **THEN** CLI 命令通过受管会话执行，控制权只作用于目标窗格

### Requirement: 人类交还 Agent

系统 SHALL 允许人类通过「交还 Agent」按钮恢复 Agent 控制权，并在转交前检查未提交输入和会话就绪状态。受管 SSH 会话 SHALL 使用后端确认的前台程序与输入状态，其他窗格 SHALL 保留既有的空提示符检查。

#### Scenario: 完成人类操作后交还
- **WHEN** 人类点击「交还 Agent」且终端处于可安全接收命令的空提示符
- **THEN** Agent 恢复控制权，界面显示蓝色光带、粒子和「agent 正在控制」
- **AND** 被接管期间拒绝的命令不会被自动重放

#### Scenario: 有未完成的输入或前台程序
- **WHEN** 人类点击「交还 Agent」时存在未提交输入，或终端无法确认可安全接收命令
- **THEN** 系统保留人类控制权并提示先完成当前输入或等待前台程序
- **AND** 系统不修改终端中的现有输入

#### Scenario: 受管 SSH 会话交还后保留 Bash
- **WHEN** 用户接管受管 SSH 会话并完成当前操作，后端确认没有未提交输入且 Bash 已就绪
- **THEN** 「交还 Agent」恢复 Agent 控制权，后续命令仍在原 Bash 执行

### Requirement: 提供一致的状态诊断

CLI SHALL 提供包含控制方、接入状态、是否存在未知结果和建议动作的结构化状态查询，同时保留现有 `session status` 文本输出兼容性。执行、接入和交还失败提示 SHALL 指向实际可用的恢复入口，仅读取状态不得获取控制权。受管 SSH 会话 SHALL 能区分 Bash 就绪、命令运行中和连接失效，并提示当前可用的接管或重新创建操作。

#### Scenario: 旧请求未知时查询
- **WHEN** 旧请求结果未知且普通执行被拒绝，调用结构化状态查询
- **THEN** 返回未知结果及用户接管后恢复失效绑定的动作，不只返回 `agent`
- **AND** 普通接入与交还错误给出一致的恢复说明

#### Scenario: 受管 SSH 会话的 CLI 等待已超时
- **WHEN** CLI 等待超时，受管连接仍在线且命令尚未确认完成
- **THEN** 查询报告命令仍未完成、CLI 结果未知，并提示可在目标窗格接管
- **AND** 查询不建议使用原有 Bash 提示符接入恢复
