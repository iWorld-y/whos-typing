# Design

## Context

`internal/sshlink` 已用系统 OpenSSH 管理 ControlMaster。独立 `ssh run` 使用 `-T`，每次启动新的远端命令。窗口中的 CLI 执行则经 `internal/control` 解析会话 ID，交给 `internal/shell.Session` 向原 PTY 写入包装命令。`internal/app` 目前将 MyGo 终端直接绑定到这个 Shell。相关动机见 [proposal.md](proposal.md)。

## Goals / Non-Goals

**Goals**

- 把会话状态、执行和输入权限交给后端，让 GUI 和 CLI 使用同一个会话状态。
- 让受管 Bash 保持目录和环境，并由独立控制通道报告就绪与命令结果。
- 保留真实 PTY 的前台输入、终端尺寸变化与中断行为。

**Non-Goals**

- 首版后端运行在现有应用进程内。应用退出后结束受管会话，无需独立常驻进程或跨应用重启恢复。
- 沿用系统 OpenSSH、现有 SSH 配置和原有 MyGo 终端依赖，首版不替换这些组件。

## Decisions

### 复用 SSH 连接，每个窗格运行自己的 Bash

新增 `ssh open TARGET` 创建受管标签页，支持沿用 `ssh --config PATH` 的配置参数。通过现有 `ssh connect` 显式建立连接后，应用复用已验证的专属 ControlMaster。创建请求沿用本地控制服务并检测受管 SSH 能力，成功返回 `session_id` 和 `tab_id`。CLI 默认保留焦点，用户可用现有 `session focus` 聚焦。后续执行沿用现有 `whos-typing-cli --session ID '命令'`。受管模式和普通标签创建使用不同入口，原有 `ssh run` 仍可在 GUI 未启动时运行。

ControlMaster 只保存传输连接。每个受管会话通过该连接启动一个远端执行组件和一个 Bash。跨命令保留目录、环境及其他 Bash 状态依靠这个 Bash。逐条执行再同步 `PWD` 和环境的方案需要重建 Shell 状态，无法覆盖 `source` 产生的完整效果。

### 把命令和 PTY 字节分开传输

远端执行组件以登录用户权限随会话启动。SSH 通道使用非 PTY 模式承载结构化消息，组件在远端为 Bash 分配 PTY。启动过程沿用现有目标校验、主机密钥校验及禁止直连回退的约束。组件采用本次会话的临时启动方式，退出后回收，不配置远端常驻服务。

- **执行和状态**。本地后端通过控制消息发送命令。远端组件通过 Bash 的独立输入通道将命令交给同一个 Bash 执行，并从独立状态通道获取就绪及退出状态。命令在原 Bash 中求值，避免在每次请求间引入子 Shell。用会话和本次执行的标识关联开始、输出边界和完成，普通 stdout、stderr 或提示符不能充当协议消息。
- **终端操作**。PTY 字节原样供终端渲染。键盘、人工粘贴、尺寸变化和终端协议应答归到对应会话的 PTY。Bash 空闲时可以接收用户的交互命令。后端在开始人工输入或提交 Agent 命令时选择一个输入方，保留尚未提交的人工输入，前台程序运行期间仅转发终端操作。

具体引导方式以隔离环境中的 Bash 作业控制验证为准。实现任务先验证独立输入和状态通道、前台进程组及 `Ctrl+C`，再接入 GUI。现有的提示符标记方案可复用 GUI 界面，但无法满足命令与终端输入分离。

隔离验证结论（见 `scripts/managed-probe/`）：组件用 Python 3 标准库 `pty.fork` 建立控制终端，依赖远端 `bash`、`python3` 和 `base64`，缺失时启动失败。命令用 `printf '%b'` 可解码的单行转义传输，状态用 Base64 字段，避免 macOS/Linux 解码参数差异。bash 3.2 的 `read -t` 超时返回 1 且被陷阱的信号不会中断阻塞的 `read`，因此交还用命令通道上的轮询请求而非信号；规范模式下未提交输入留在内核行缓冲，轮询不丢失。登录 Shell 初始化可能向 stdout 打印文本，组件先输出随机同步标记，后端从标记后解析帧。DONE 状态帧发出前先排空已到达的 PTY 输出，保证最后一段输出计入结果。粘贴由组件完整写入 PTY（处理短写）后回 POK 回执，后端收到回执才报告成功；人工空行也发完成通知以消费输入计数。

### 后端集中处理执行状态，GUI 显示同一次运行

本地后端负责 SSH 进程、会话生命周期、控制权和在途请求。GUI 使用现有终端组件展示 PTY 输出，用普通文本显示命令及最终结果，继续使用现有接管和交还按钮。CLI 沿用执行结束后返回输出和退出码的协议。PTY 模式下显示合并后的终端流，现有 `ssh run -T` 继续分别转发 stdout 和 stderr。GUI 切换标签和 CLI 停止等待均不阻塞远端输出消费。

每个 Bash 同时只处理一条命令。后端统一判断能否提交和接管，防止先检查权限再发送时发生竞态。用户接管时取消尚未发送的请求，完成通知只作用于对应请求。用户退出前台程序且 Bash 回到可执行状态后可以交还。沿用已有的主动交还、空闲 60 秒自动交还、会话快照和输入保护规则。受管会话通过后端就绪信息完成交还。原有 `attach` 和恢复接入继续服务原路径。受管窗格如果收到 `session paste` 请求，沿用现有的窗格绑定、输入保护和确认规则，获准后只向 PTY 粘贴，不追加 Enter。

### 将 CLI 等待时间和会话生命周期分开

CLI 超时或断开只结束该次等待。已受理命令仍由后端追踪，直至收到明确的完成通知或确认会话失效。已确认未发送则报告未执行，发送结果不明或会话丢失则报告结果未知。收到远端命令的结构化退出状态时按原值返回，包括远端实际报告的 255。若只有 SSH 进程退出码 255 且没有该命令的完成通知，则报告结果未知。应用不重试旧命令。关闭一个受管窗格只清理它的执行通道和订阅。显式 `ssh disconnect` 仍会关闭目标 master，影响复用该连接的所有通道。

## Risks / Trade-offs

- 前台程序占用 Bash 时，后端拒绝另一条请求，并提供接管入口。原 Bash 要在前台程序退出后才能继续执行。
- `Ctrl+C` 由当前远端 PTY 和前台程序按终端规则处理。应用等待实际退出通知。对自行退出、替换进程或导致 Bash 退出的命令，应用报告会话结束，并提示重新创建。
- 长输出使用有界缓冲或复用现有输出文件。终端输出和完成通知各自有序到达时，后端需确保最后一段输出被计入结果，再完成 CLI 回包。
- 默认远端验收使用 Bash 和可分配 PTY 的隔离 SSH 目标。远端引导、依赖或版本不满足时返回启动失败，保留原布局。

## Migration Plan

新能力通过显式入口启用。既有窗格无需迁移，原有命令和本地设置仍可使用。需要回退时关闭受管窗格并使用既有终端或独立 `ssh run`，无需迁移会话数据或移除远端常驻服务。
