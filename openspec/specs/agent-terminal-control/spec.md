# agent-terminal-control Specification

## Purpose

定义 Agent 与人类如何在同一终端会话中切换控制权，使用户能够识别当前控制方、随时接管并在合适时机交还，同时保持命令执行和终端内容可观察。

## Requirements

### Requirement: CLI 操作获取 Agent 控制权

系统 SHALL 将通过 CLI 向终端发送执行命令或自动接入输入视为 Agent 操作，并在终端可安全接收输入且未被用户主动接管时给予 Agent 控制权。人工运行 CLI 使用相同行为。控制权变化 SHALL 仅作用于请求绑定的会话。

#### Scenario: CLI 在空闲终端执行命令
- **WHEN** 用户未主动接管，终端停在可接收命令的空提示符，CLI 发起执行请求
- **THEN** 系统切换到 Agent 控制状态并执行该命令
- **AND** 请求按会话路由规则确定目标，原有命令输出和退出状态行为保持可用

#### Scenario: 人类已有未提交输入
- **WHEN** 人类已有未提交输入，CLI 发起执行请求
- **THEN** 系统拒绝请求并保留人类输入
- **AND** 系统不得为了接管而提交、清除或覆盖这些输入

#### Scenario: 只读请求不获取控制权
- **WHEN** CLI 调用 `session read` 读取终端快照
- **THEN** 系统返回快照，不因读取而切换控制权
- **AND** 读取不重置 Agent 的空闲计时

### Requirement: 显示控制权与视觉效果

系统 SHALL 在 Agent 持有控制权的整个期间显示蓝色边缘光带、动态粒子和位于终端顶部中央的半透明毛玻璃胶囊，胶囊包含文本「agent 正在控制」及「接管」按钮。人类持有控制权时 SHALL 移除 Agent 特效。每个窗格 SHALL 独立显示控制状态，光带、粒子和胶囊限定在对应窗格内。

#### Scenario: Agent 在命令间继续控制终端
- **WHEN** 一条 Agent 命令结束，Agent 仍持有控制权
- **THEN** 蓝色光带、粒子和包含「agent 正在控制」「接管」的顶部胶囊保持显示
- **AND** 系统不因单条命令结束立即隐藏特效或胶囊

#### Scenario: 控制权切换到人类
- **WHEN** 控制权交给人类
- **THEN** Agent 特效渐隐并消失
- **AND** 手动接管期间，顶部胶囊显示「人类正在控制」和「交还 Agent」按钮

#### Scenario: 使用减少动态效果设置
- **WHEN** Agent 持有控制权且系统启用减少动态效果
- **THEN** 界面保留可辨认的控制状态提示，并停止持续动态效果

#### Scenario: 控制栏的范围
- **WHEN** 系统显示控制胶囊
- **THEN** 系统不显示「终止任务」按钮
- **AND** 胶囊以外的终端内容可正常查看、选择和滚动，用户可以使用接管按钮

#### Scenario: 胶囊悬浮在终端上方
- **WHEN** 系统显示控制胶囊
- **THEN** 胶囊位于终端内容区域的顶部中央，不在顶部或底部预留整行空间
- **AND** 胶囊可以局部遮挡其下方的终端文字

#### Scenario: 显示通透的毛玻璃背景
- **WHEN** 系统显示控制胶囊
- **THEN** 终端内容与其上方的粒子效果可以透过胶囊，并在胶囊背景区域呈现模糊效果
- **AND** 胶囊内的状态文字、错误提示和操作按钮仍清晰可辨

#### Scenario: 单行胶囊的文字垂直居中
- **WHEN** 控制胶囊以单行展示状态和按钮，且没有错误提示
- **THEN** 状态文字在胶囊内视觉上上下居中
- **AND** 按钮文字在按钮内视觉上上下居中

#### Scenario: 人类交还时终端尚未就绪
- **WHEN** 人类点击「交还 Agent」，但终端有未完成输入或无法确认就绪
- **THEN** 系统继续显示人类控制状态与「交还 Agent」按钮，并提示交还失败的原因

#### Scenario: Agent 自动或主动交还
- **WHEN** Agent 自动或主动将控制权交给人类，且人类没有手动接管
- **THEN** 控制胶囊消失，终端仍可由人类操作

### Requirement: 人类立即接管终端

系统 SHALL 在用户点击「接管」后立即将输入控制权交给人类，并阻止后续 Agent 写入。已开始的命令 SHALL 继续运行，不因接管而自动中断。

#### Scenario: 接管正在执行的命令
- **WHEN** Agent 命令正在运行，用户点击「接管」
- **THEN** 用户可以立即向当前前台程序输入
- **AND** 系统不因接管发送 Ctrl+C 或终止命令
- **AND** 命令输出继续显示，用户可以自行按 Ctrl+C

#### Scenario: 接管与排队命令并发
- **WHEN** 用户接管时，Agent 命令尚在排队且未开始发送到终端
- **THEN** 该命令不会在接管后发送或等待日后自动执行
- **AND** CLI 收到未执行的状态反馈

#### Scenario: 命令发送状态不明
- **WHEN** 用户接管时，系统无法确认正在发送的命令是否已经执行
- **THEN** 系统报告结果未知，不自动重试或声称命令已停止

### Requirement: 人类接管期间 Agent 只读

用户主动接管后，系统 SHALL 拒绝 Agent 的新执行请求及自动输入请求，直到用户明确交还控制权；系统 SHALL 继续允许 Agent 读取终端快照和接收已开始命令的输出。

#### Scenario: Agent 在人类控制期间尝试执行
- **WHEN** 人类持有通过「接管」获得的控制权，CLI 发送新的执行请求
- **THEN** 系统提示终端由人类控制并拒绝执行
- **AND** 被拒绝的命令不会在交还后自动执行

#### Scenario: Agent 观察人类操作
- **WHEN** 人类控制终端且 Agent 调用 `session read`
- **THEN** Agent 可以按现有快照规则读取终端内容
- **AND** 已开始命令的输出仍可返回给原 CLI 请求

#### Scenario: 手动接管超过一分钟
- **WHEN** 人类主动接管后超过 60 秒没有 Agent 命令
- **THEN** 系统保持人类控制和「交还 Agent」入口
- **AND** Agent 不会因空闲计时而自动重新接管

### Requirement: 人类交还 Agent

系统 SHALL 允许人类通过「交还 Agent」按钮恢复 Agent 控制权，并在转交前保留现有的未提交输入和终端就绪检查。

#### Scenario: 完成人类操作后交还
- **WHEN** 人类点击「交还 Agent」且终端处于可安全接收命令的空提示符
- **THEN** Agent 恢复控制权，界面显示蓝色光带、粒子和「agent 正在控制」
- **AND** 被接管期间拒绝的命令不会被自动重放

#### Scenario: 有未完成的输入或前台程序
- **WHEN** 人类点击「交还 Agent」时存在未提交输入，或终端无法确认可安全接收命令
- **THEN** 系统保留人类控制权并提示先完成当前输入或等待前台程序
- **AND** 系统不修改终端中的现有输入

### Requirement: Agent 主动交还

系统 SHALL 提供 CLI 操作，使 Agent 完成终端工作后能够主动交还控制权。

#### Scenario: Agent 主动交还空闲终端
- **WHEN** Agent 持有控制权，终端没有待发送或运行中的命令，Agent 请求交还
- **THEN** 人类获得控制权，Agent 特效消失
- **AND** 系统不关闭终端会话

#### Scenario: 人类已主动接管时收到交还请求
- **WHEN** 人类已经点击「接管」，CLI 发送主动交还请求
- **THEN** 系统保持人类手动接管状态，并继续拒绝 Agent 输入
- **AND** 只有人类点击「交还 Agent」才能恢复 Agent 控制权

### Requirement: 命令完成后空闲一分钟自动交还

Agent 持有控制权时，系统 SHALL 从命令确认结束后开始计算空闲时间。终端没有待发送或运行中的命令，且连续 60 秒没有新的执行命令时，系统 SHALL 自动将控制权交给人类。

#### Scenario: 长命令结束后重新计时
- **WHEN** 一条 Agent 命令运行超过 60 秒后结束
- **THEN** 系统不会在命令运行期间或刚结束时因空闲超时交还
- **AND** 系统从该命令结束后重新计算 60 秒

#### Scenario: 期间收到新命令
- **WHEN** Agent 命令结束后未满 60 秒，系统接受新的执行命令
- **THEN** 系统取消先前的空闲计时
- **AND** 新命令结束后重新计算 60 秒

#### Scenario: 命令启动后台服务
- **WHEN** Agent 执行 `systemctl start` 并且该命令已结束，而服务仍在后台运行
- **THEN** 系统将这条命令视为已结束并开始空闲计时
- **AND** 系统不等待后台服务退出

#### Scenario: 远端命令状态未知
- **WHEN** 远端 CLI 请求超时或连接断开，系统无法确认命令是否结束
- **THEN** 系统不得把请求结束当作命令结束并据此自动交还
- **AND** 用户仍可手动接管终端

### Requirement: 自动交还后允许重新接管

系统 SHALL 在自动交还后允许新的 Agent 执行请求重新获取控制权，但不得覆盖人类输入或抢占正在使用的终端。

#### Scenario: 自动交还后终端空闲
- **WHEN** 空闲超时已将控制权自动交给人类，且终端仍处于可安全接收命令的空提示符
- **AND** CLI 发起新的执行请求
- **THEN** 系统重新切换到 Agent 控制状态并执行新命令

#### Scenario: 自动交还后人类开始操作
- **WHEN** 空闲超时已交还控制权，人类有未提交输入或前台程序正在运行
- **AND** CLI 发起新的执行请求
- **THEN** 系统拒绝请求并保持人类控制
- **AND** 系统不得覆盖输入或中断前台程序

### Requirement: 会话间控制权独立

每个会话 SHALL 独立处理接管、交还、输入保护与空闲计时。切换焦点、创建会话以及其他会话的命令和控制操作 SHALL 不改变该会话控制权；隐藏标签页 SHALL 继续维护控制状态与计时。

#### Scenario: 人类与 Agent 操作不同窗格
- **WHEN** Agent 在 A 执行命令，用户在 B 输入
- **THEN** B 的输入正常发送到 B，A 的状态和命令不受影响
- **AND** 用户接管 A 不会阻止 Agent 操作未被接管的其他会话

#### Scenario: 隐藏会话自动交还
- **WHEN** A 的命令已结束且符合空闲交还条件，用户正在其他标签页操作
- **THEN** A 按既有 60 秒规则交还，不受其他会话活动影响
- **AND** 切回 A 时显示 A 的最新控制状态

### Requirement: 自动接入确认明确绑定会话

自动远端接入 SHALL 始终绑定目标会话及标签页。自动允许关闭时，确认 SHALL 标明目标会话 ID 和标签页，用户 SHALL 能查看目标窗格后确认；自动允许开启时，首次接入 SHALL 无需确认框。焦点变化不得替换目标，目标关闭或请求取消 SHALL 使申请失效。两种模式 SHALL 保留控制权、人工输入、前台进程组及申请期间终端变化检查，新握手完成前不得执行业务命令。

#### Scenario: 确认过程中切换焦点
- **WHEN** 自动接入请求绑定 A，用户在确认前切换到 B
- **THEN** 确认仍明确指向 A，只能向 A 发送接入输入
- **AND** 发送前重新检查 A 的空提示符和控制权，不向 B 注入输入

#### Scenario: 确认目标已关闭
- **WHEN** A 的接入确认尚未完成而 A 被关闭
- **THEN** 请求结束并提示目标不可用，旧确认不能作用于新会话

#### Scenario: 自动允许首次接入
- **WHEN** 自动允许已开启，用户已在 A 登录目标交互式 Bash，CLI 发起自动接入且现有输入及进程组检查通过
- **THEN** 仅向 A 发送一次接入命令，不弹出确认框
- **AND** 只有握手成功后才允许执行命令

#### Scenario: 自动允许不能覆盖保护条件
- **WHEN** 自动允许已开启，但用户主动接管、存在未提交输入，或接入期间终端输入、输出、前台进程组发生变化
- **THEN** 接入被拒绝，不修改人工输入，不向其他会话发送命令

### Requirement: 接入 Shell 退出通知

系统 SHALL 在收到当前接入 Shell 的有效退出通知时使该接入失效，并结束等待中的 CLI 请求，不等待其原超时耗尽。缺少命令完成证据时 SHALL 报告结果未知，不将 Shell 退出码当作完整业务命令结果。系统 SHALL 不将普通提示符文本或子 Shell 退出当作有效退出通知。

#### Scenario: 内层 Bash 因 errexit 退出
- **WHEN** 接入的内层 Bash 保留了 `set -e`，后续失败命令使其退出并发出有效退出通知，SSH 内的外层 Bash 仍然存活
- **THEN** 等待中的 CLI 收到接入已失效、命令结果未知的错误
- **AND** 当前窗格和 SSH 保留，用户获得可操作的恢复提示

#### Scenario: 命令启动子 Shell
- **WHEN** 业务命令中的子 Shell 退出，但接入的 Bash 仍然存活
- **THEN** 接入保持有效，不因子 Shell 的退出而终止当前请求

#### Scenario: 退出钩子不可用
- **WHEN** 钩子被覆盖或 Shell 异常终止，系统无法获取可信完成或退出通知
- **THEN** 保留结果未知的状态，允许用户发起失效绑定恢复，不自动推断命令已停止

### Requirement: 用户确认后恢复失效绑定

系统 SHALL 在用户主动接管后提供恢复失效绑定的入口，包括旧 CLI 仍在等待、超时或取消后结果未知的情况。恢复 SHALL 要求用户明确确认目标 Bash 空提示符及放弃旧请求等待，即使自动允许设置已开启。确认后 SHALL 保留旧结果未知的记录，作废旧绑定并建立新握手，不重放旧命令、不关闭 SSH、不向旧命令发送终止信号。未完成的输入和仍在发送的命令字节 SHALL 阻止接入注入。

#### Scenario: 超时或取消后恢复
- **WHEN** 用户确认旧接入已失效、当前为目标 Bash 空提示符，并发起恢复
- **THEN** 旧请求不再阻塞新握手，原结果仍标为未知
- **AND** 新握手完成后恢复同一窗格的 Agent 控制，无需新开会话

#### Scenario: CLI 仍等待旧请求
- **WHEN** 旧 CLI 仍在等待，用户确认恢复且旧输入发送已经结束
- **THEN** 旧 CLI 收到等待已放弃、结果未知的错误，新接入使用独立标识

#### Scenario: 取消恢复或状态改变
- **WHEN** 用户取消恢复，或确认期间发生新输入、输出、前台进程变化或目标关闭
- **THEN** 不注入接入命令，保留人类控制和未知结果，并允许以后再次申请恢复

#### Scenario: 旧通知迟到
- **WHEN** 恢复后收到旧接入的完成或提示符通知
- **THEN** 通知不能完成新请求、改变新控制状态或开放新接入

### Requirement: 提供一致的状态诊断

CLI SHALL 提供包含控制方、接入状态、是否存在未知结果和建议动作的结构化状态查询，同时保留现有 `session status` 文本输出兼容性。执行、接入和交还失败提示 SHALL 指向实际可用的恢复入口，仅读取状态不得获取控制权。

#### Scenario: 旧请求未知时查询
- **WHEN** 旧请求结果未知且普通执行被拒绝，调用结构化状态查询
- **THEN** 返回未知结果及用户接管后恢复失效绑定的动作，不只返回 `agent`
- **AND** 普通接入与交还错误给出一致的恢复说明
